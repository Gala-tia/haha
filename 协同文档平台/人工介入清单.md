**方式 A · 命令行**（重开终端后）：


**方式 B · 免配置（推荐）**：直接双击项目目录里的 **`start-server.bat`**，脚本会自动把 Node 目录加进本次窗口的 PATH 并启动服务，不依赖系统环境变量。

浏览器打开 **http://localhost:3000/admin.html**

1. 填成员名、选角色，点「签发链接」，复制生成的链接；
2. 建议签 3 条：**2 条 editor（可编辑）+ 1 条 viewer（只读）**；
3. 用两个浏览器窗口（或一个普通窗口 + 一个无痕窗口）分别打开两条 editor 链接；

6. 命令行签发：`npm run gen-link -- 张三 editor doc-1`。

> 前置名词：`npm start` = 按 package.json 里的脚本启动服务；`端口 3000` = 浏览器访问的地址编号；`无痕窗口` 用来模拟「另一台设备/另一个人」，因为两个窗口的登录态互不相通，正好验证同一条链接在不同终端的表现。

## 四、第 8 项可用的真实边界（不是预留的假 bug）

以下是本实现范围内确实没覆盖到的地方，测试时容易撞到，照实记录即可：

- 编辑输入有 200ms 防抖，**在防抖窗口内强关标签页/断网，最后一次输入可能未提交**；
- 中文输入法组词期间会触发 `input` 事件，可能把拼音中间态广播给其他人；
- 广播是**整段 html 替换**，其他窗口的滚动位置与选区会被重置；
- 两个窗口几乎同时点「开始编辑」，服务端按消息到达顺序裁决，**没有排队机制**，后到者只看到一条被拒提示；
- 服务重启时若有人持锁，在线会话与锁清空，该次编辑**不会补生成版本**（表 4-18 已声明）；
- 只读链接虽不能写，但仍可查看/下载历史版本（角色约束只作用于写入权）；
- 令牌明文存于 `data/links.json`，拿到文件即可看到全部链接 —— 这是**已知限制**，按第 3 章口径本期不实现安全防护，不要当功能缺陷报。

这些不是刻意埋的假 bug，是最小原型本来的边界。你测试时撞到别的，也照实记，比套用这份清单更真实。
